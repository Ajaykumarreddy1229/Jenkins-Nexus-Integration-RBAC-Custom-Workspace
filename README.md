# 2. Jenkins Integration with Nexus

## What is Nexus?

**Nexus Repository Manager** is an artifact repository used to store and manage build artifacts.

For example:

```text
Java Application
       ↓
     Maven
       ↓
   WAR Artifact
       ↓
     Nexus
       ↓
Store Artifact
```

Instead of keeping build artifacts only inside the Jenkins workspace, they can be uploaded to a repository such as Nexus.

# 9. Nexus Artifact Upload

Example Jenkins Pipeline step:

```groovy
nexusArtifactUploader(
    artifacts: [[
        artifactId: 'myapp',
        classifier: '',
        file: 'target/myapp.war',
        type: '.war'
    ]],
    credentialsId: 'nexuscreds',
    groupId: 'in.reyaz',
    nexusUrl: 'NEXUS_IP:8081',
    nexusVersion: 'nexus3',
    protocol: 'http',
    repository: 'hotstar',
    version: '8.3.3-SNAPSHOT'
)
```

### Important Parameters

```text
artifactId
    ↓
Name of the artifact

file
    ↓
Artifact file to upload

credentialsId
    ↓
Jenkins credential used to authenticate with Nexus

groupId
    ↓
Maven group identifier

nexusUrl
    ↓
Nexus server URL

repository
    ↓
Nexus repository name

version
    ↓
Artifact version
```

> Replace the Nexus IP, repository name, credentials ID, group ID, artifact ID, and version with the values used in your own environment.

## What is RBAC?

**RBAC** stands for:

# 14. Authentication vs Authorization

These two concepts are important for Jenkins security.

## Authentication

Authentication determines whether a user is allowed to sign in.

```text
User
 ↓
Login
 ↓
Authentication
 ↓
Is the user valid?
```

---

## Authorization

Authorization determines what an authenticated user is allowed to access or perform.

```text
Authenticated User
        ↓
  Authorization
        ↓
What can the user do?
        ↓
Jobs / Builds / Configuration
```

---

# 15. Authentication vs Authorization – Simple Example

```text
Authentication
       ↓
Can the user enter Jenkins?

Authorization
       ↓
What can the user do inside Jenkins?
```

### Example

A user may be able to log in to Jenkins but may not have permission to:

* Create jobs
* Delete jobs
* Configure jobs
* Build specific jobs
* Manage Jenkins
* Manage users

# 16. Project-Based Permissions

I also practiced **Project-Based Matrix Authorization**.

This allows permissions to be controlled at the individual project/job level.

Example:

```text
Jenkins
   |
   ├── Project-A
   │      └── User-A → Build
   |
   ├── Project-B
   │      └── User-B → Read
   |
   └── Project-C
          └── Admin → Full Access
```

This provides more granular access control.

# 17. Custom Workspace

## What is a Jenkins Workspace?

A workspace is the directory where Jenkins performs operations for a job.

Typical operations include:

```text
Checkout Code
     ↓
Compile
     ↓
Test
     ↓
Package
```

Jenkins normally creates and manages the workspace automatically.

---

# 18. What is a Custom Workspace?

A **custom workspace** allows us to specify a particular directory where a Jenkins job should execute.

Example:

```text
/home/ec2-user/reyaz
```

Instead of using the default Jenkins workspace, the job can use the specified directory.

---

# 19. Configure Custom Workspace

In a Jenkins job:

```text
Jenkins Job
    ↓
Configure
    ↓
General
    ↓
Advanced
    ↓
Use custom workspace
    ↓
Specify Directory
```

Example:

```text
/home/ec2-user/reyaz
```

# 21. Linux Permissions

When Jenkins uses a custom workspace, the Jenkins user needs appropriate permissions to access that directory.

Linux permissions can affect the Jenkins build.

For example, check the directory permissions using:

```bash
ls -al
```

Check:

```text
Owner
Group
Permissions
Directory Access
```

---

# 22. Custom Workspace Troubleshooting

If Jenkins cannot access the custom workspace, check:

```text
1. Directory exists
2. Jenkins user has access
3. Directory ownership
4. Directory permissions
5. Parent directory permissions
```

Basic command:

```bash
ls -al
```

The important relationship is:

```text
Jenkins Job
     ↓
Custom Workspace
     ↓
Linux File Permissions
     ↓
Jenkins User Access
     ↓
Build Success
```
